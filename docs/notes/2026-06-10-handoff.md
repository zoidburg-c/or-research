## Open work (in priority order)

### 1. Fix the eval-utility bug — unblocks the failing 4th acceptance criterion

**Where:** `experiments/runner.py:237-240`

```python
eval_weights = np.ones(cfg.num_objectives) / cfg.num_objectives
eval_u = linear_utility(eval_weights)         # <-- always linear
ser = evaluate_ser(episode_returns, eval_u)
esr = evaluate_esr(episode_returns, eval_u)
```

**Why it's a bug:** For linear `u`, `u(E[r]) ≡ E[u(r)]` by Jensen — so `ser` and `esr` are mathematically forced to be identical regardless of how the agent trained. The 2026-05-26 sweep confirmed: SER == ESR exactly in all 16 configs.

**Suggested fix:** evaluate with the config's actual utility, not a hardcoded linear one. Reuse the helper that already exists:

```python
from momas.config import _make_utility_fn  # already imported indirectly via momas
# … in run_experiment, after computing eval_weights …
eval_u = _make_utility_fn(eval_weights, cfg.momas_criterion)
ser = evaluate_ser(episode_returns, eval_u)
esr = evaluate_esr(episode_returns, eval_u)
```

`_make_utility_fn` lives in `experiments/runner.py:62`. It returns `threshold_utility` when criterion is `ESR` and `linear_utility` otherwise. With this fix, ESR configs will use `threshold_utility` for both training and eval, and `ser != esr` whenever `episode_returns` has variance.

**Verify by:** re-running the two `team_team_esr` configs and confirming `SER != ESR` is now reported. Acceptance criterion 4 from the taxonomy-gaps plan passes.

**Add a test:** `tests/test_runner.py` should get a case asserting `results["ser"] != results["esr"]` for an ESR config (use a small `num_episodes` to keep it fast).

### 2. Fix the npz output-path collision

**Where:** `experiments/runner.py:254-263`

```python
out_dir = Path(cfg.output_dir) / cfg.env / f"{cfg.momas_reward_structure}-{cfg.momas_utility_type}"
np.savez(out_dir / f"seed_{cfg.seed}.npz", ...)
```

**Why it's a bug:** The path ignores `cfg.momas_criterion` and `cfg.agent_type`. The four `team_team*` configs per domain (`team_team`, `team_team_esr`, `team_team_dqn`, `team_team_envelope`) all write to `results/<env>/team-team/seed_42.npz` and silently overwrite each other. Only the last-run config survives on disk.

**Suggested fix:** include criterion and agent_type:

```python
out_dir = (
    Path(cfg.output_dir)
    / cfg.env
    / f"{cfg.momas_reward_structure}-{cfg.momas_utility_type}"
    / f"{cfg.momas_criterion}-{cfg.agent_type}"
)
```

**Verify by:** running the full sweep and confirming each config produces its own `.npz` (16 files total across both env directories).
